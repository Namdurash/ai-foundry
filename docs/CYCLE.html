AI Foundry Cycle

Two halves, one boundary. The human half is a conversation with no gates: it decides what is worth building and writes it down. The machine half is headless and never asks: it builds what the ticket says, and a gate judges every station. They meet only on the board.

  • Human time — a skill, run when you want, for as long as you want
  • The board — where the state is seen; every move goes through aif board
  • Machine time — aif work, one ticket, one worktree, no questions; aif land is the yes after review
  • Hexagons are gates: a verdict, retried with the complaint, never a conversation
  • The rounded node is the request itself, a file with a status line the analyst keeps true

The human halfRoles

Each is a skill under sets/claude/skills/ and a slash command of the same name. /aif-setup says which can run on this machine.

What passes between the first two is a file, requests/<slug>.md, with a status of its own: not cut when the product partner writes it, cut in part with one line per slice once the analyst has made cards, cut when every slice has one.

The boundaryThe board

backlog → ready → in progress → review → done, plus Needs Human: the columns lib/board.sh knows, on a local board or on Trello. The first slice's ticket lands in Ready; the other slices wait in Backlog, and aif land releases each one when the tickets it depends on are Done.

The machine halfStations and gates

The stage order is the list in lib/run.sh; each station's own file names the gate that judges it. The ready gate runs first, at intake, before the first token: the same script the analyst ran at the end of the conversation.

How this stays true. Nothing here was typed in: scripts/cycle.sh reads the stations, gates, columns, roles and caps from the files that define them, asserts the facts that live in control flow, and writes docs/CYCLE.md and this page. make check fails while either is stale.
